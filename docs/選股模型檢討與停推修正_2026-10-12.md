# LINE 選股模型檢討與停推修正

檢查日：2026-10-12，台北時間。程式修正版本：bcfcda4。

## 停推原因與證據

1. 9/24 的主推播成功，分析 220 檔，訊息 3,362 字元。
2. 9/25、9/28 是證交所公告休市日。舊程式把交易日仍是 9/24 判為「共同交易日未更新」，在 LINE 發送前中止。
3. 第二則找不到當日第一則名單，未發送卻以成功狀態結束。
4. GitHub 原生排程經常延遲到凌晨。時段保護正確地跳過推播，但舊 watchdog 把綠燈的跳過流程誤認為成功，不再補觸發。
5. repo 最後一次程式提交在 7/28；GitHub 已明確顯示因超過 60 天沒有活動而停用排程，9/28 後無新的正常觸發紀錄。
6. 外部 cron-job.org 兩筆工作仍啟用。恢復 GitHub 排程後，兩筆呼叫均回傳 HTTP 204；現有 Token 的有效期至台北 2026-12-31 00:00，因此目前不是 Token 過期。
7. 兩筆外部工作原本未啟用每次執行失敗通知，已啟用失敗及恢復通知。歷史回應未保存，不能聲稱已取得每次歷史失敗的 HTTP 碼。

官方休市來源：https://www.twse.com.tw/zh/trading/holiday.html
GitHub 停用規則：https://docs.github.com/en/actions/how-tos/manage-workflow-runs/disable-and-enable-workflows

## 本次修正

- 依官方交易日曆跳過休市日，以「應有的最新交易日」核對日期。正常交易日缺資料仍阻擋正式推薦。
- 第一則以 LINE API 接受結果建立發送紀錄；沒有實際受理，不建立已發送標記。
- 第二則正式推播需要第一則的當日正式發送憑證，且資料日正確。白天測試名單不能當成晚間正式名單。
- 第二則缺名單時保留等待紀錄並回傳失敗，供後續重試，不再以綠燈掩蓋。
- watchdog 檢查發送步驟與正式標記，並同時照顧兩則報告。跳過的成功流程不代表已送達。
- LINE 使用每日、每種報告各自的重試識別碼；暫時網路或伺服器問題安全重試，避免同日重複受理。
- 每次嘗試保留不含 Token、收件者 ID、原始錯誤內容的 JSON 結果，供稽核。
- 每週檢查測試及日曆，每月保存一次實際營運檢查紀錄，以維持 repo 活動並檢查排程狀態。
- 官方 Actions 升級至支援 Node.js 24 的版本；兩筆外部工作仍維持台北 20:00、21:15。

GitHub 排程為盡力執行，不能保證整個平台不延遲。外部呼叫 HTTP 204 僅代表 GitHub 受理；真正完成須檢查 LINE 受理紀錄。LINE API 受理也不是使用者閱讀確認。

臨時休市可使用 AI_STOCK_EXTRA_CLOSED_DATES 變數；不得把來源故障推論成颱風休市。年底需驗證下一年度日曆，未知日曆不能直接假設所有平日開市。

## 現在模型的優點

第一層建立上市櫃可投資母體；第二層分開計算基本面、早期資金與位置；第三層合併基本面成長、轉折、法人早期建倉、產業突破及非主流突破入口，再深入分析最多 220 檔。每日會重建並保存候選雜湊與進出原因。

正式 Top 有基本面底線、流動性、過熱、法人當日轉賣及分散限制。產業只設上限，沒有湊滿檔數的最低配額。Gemini 覆判候選股，不代替數字與風險門檻。

## 尚不足以「比法人更早發現」的部分

| 項目 | 現有缺口 | 影響與改善 |
| --- | --- | --- |
| 營收加速 | 當月 YoY、MoM 與累計 YoY，未建立一致的多月歷史 | 低基期、季節性與一次性成長可能被誤當加速。加入 3／6／12 月營收、同月份比較及連續改善。 |
| EPS 趨勢 | 前期值依賴快取；同季每天更新後前期 EPS 參考可能消失 | 保存各財務期間，不只最新一筆；核對單季、累計與同期，再計算 QoQ／YoY。缺前期資料不能視為前期虧損或轉虧為盈。 |
| ROE 與估值 | 淨利乘四除期末權益、EPS 年化回推 | 若來源為累計值或權益大幅改變，可能失真。優先使用四季 EPS、四季淨利及平均權益，清楚標示估算。 |
| 現金流與品質 | FinMind 補充只覆盖部分候選，其餘可能使用中性值 | 以官方財報擴大覆蓋現金流、應收帳款、存貨、負債；中性缺資料不是確認品質良好。 |
| 法人前置偏好 | 多個資金入口要求法人已偏買；最終排名也受籌碼分數影響 | 保留正式 Top 標準，另設基本面改善但法人未確認的觀察入口，避免先要求股價與法人已發酵。 |
| 產業相對強度 | 以母體中位數作基準，且統計已被流動性篩選的同業 | 改為官方產業母體並與 0050／加權比較，另標明可投資覆蓋率。 |
| 法人金額 | 用淨股數乘收盤價估算 | 是資金強度近似值，不是法人逐筆真實成交金額；同日分母與歷史窗口須一致。 |
| Gemini 與新聞 | 第一則預設僅三檔且未開 Search；第二則八檔可搜尋 | 被候選池排除的公司不會被 Gemini 發現。需在前段加入帶公告日的公開資訊與事件篩選。 |
| 證據與回測 | 來源數量不是逐一引述；尚無已驗證的漏網／樣本外回測 | 保留來源連結、日期與主張；衡量是否在起漲前 5／10 日入池及被排除原因。 |

## 建議優先順序

1. 先改善資料品質：多期財報與營收、單季／TTM、估值年化與現金流覆蓋率，避免分數因缺值或快取而漂移。
2. 新增「營運轉折觀察」：營收多月加速、毛利／營益率同季改善、現金轉換可接受、股價未過熱。法人未買不是排除條件，但明顯派發、事件風險與資料不完整仍需處理。不設定必須湊滿的股票數。
3. 以公開資訊觀測站重大訊息、公司法說會與營運公告提供帶日期的證據。Gemini 摘出成長來源、可持續性、催化與風險，缺證據明說待驗證。
4. 每日漏網稽核：20 日漲幅前 30 名，檢查是否於起漲前 5／10 日入池，列出流動性、產業、財報、技術或風險阻擋原因。
5. 使用當時可知的資料、含下市股票與除權息調整，比較 5／20／60 日前瞻績效、成本、最大回撤與 0050；通過後才改權重。

「法人尚未發現」不能由買賣超資料證明，沒有買進也不代表沒有研究。可驗證的目標應是：在明顯法人集中買超與股價急漲前，找到已有營運改善證據、仍在合理位置的觀察標的。Gemini 的信心分數不是上漲機率，目前也不能據此宣稱已能穩定打敗 0050。
